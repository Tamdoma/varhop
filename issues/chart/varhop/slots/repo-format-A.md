# Slot A notes: repo-format

Evidence: [better-than-training] VS Code prompt files docs https://code.visualstudio.com/docs/copilot/customization/prompt-files (read 2026-10-12): Markdown with optional YAML header (description, name, argument-hint, agent, model, tools); `name` defaults to the file name. [better-than-training] Fabric (Daniel Miessler) lays out one folder per pattern, `patterns/<name>/system.md`, plain Markdown, no front matter (search results 2026-10-12; its `{{input}}` syntax NOT confirmed). No practitioner write-up found on prompt-library repo layouts.

Q1 Layout. Pick: `prompts/<category>/<subcategory>/<slug>.md`, exactly two folder levels, under a `prompts/` folder so the repo can also hold README/other files. Reason: operator asked for categories and subcategories; fixed depth gives the UI a stable shape (category list, then subcategory, then prompt). Cost: no prompts at category root, no deeper nesting. Rejected: any depth (UI must handle unbounded trees), single index file (merge conflicts, one bad line breaks all), repo root as content root (every docs folder becomes a category).
Q2 Front matter. Pick: all optional YAML front matter: `title` (default: file name, hyphens to spaces), `description`, `tags` (list). Reason: search fields, matches VS Code precedent, lenient for hand-written files. Cost: a small YAML-subset parser in JS (title/description/tags only). Rejected: required fields (any typo hides a prompt), none (nothing but filename to search).
Q3 Variables. Pick: `{{NAME}}`, NAME = letters, digits, underscore (starts with letter or underscore), any case. Any other `{{...}}` (spaces, dots, triple braces) stays literal text so prompts about Jinja/Handlebars survive. `\{{NAME}}` forces literal. No defaults or hints in v1 (operator did not ask; the name is the hint). Cost: variable names with spaces unsupported. Rejected: defaults/descriptions in front matter (extra schema, not requested), unrestricted names.
Q4 Marker. Pick: none in v1. The `prompts/` folder is the marker; absent folder = "not a varhop repo" message in settings. Add a versioned manifest only when a second format version exists. Cost: a v2 must detect v1 by absence. Rejected: manifest now (a file that holds nothing yet; B's schema-evolution point is real but deferrable).

Pitfalls: bad front matter -> show the file in a per-file error list, load the body anyway; file outside the two levels -> listed as ignored, not silently dropped; duplicate slugs in one subcategory impossible (filesystem). Name-clash between folder names and display (kebab-case folders shown as Title Case) -> display rule decided in leaf.
