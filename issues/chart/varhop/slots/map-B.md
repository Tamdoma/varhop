## 2. Forks

- **F1. Which native surface meets “above everything” and instant summon?** Standalone Qt/QML floating app matches the published app pattern and isolates failures, but needs single-instance IPC, compositor placement/focus handling and a fullscreen proof. Keep-loaded Quickshell overlay reuses the existing layer/focus/theme lifecycle, but depends on shell APIs and shares shell restart/failure effects. Standalone Qt with a layer-shell dependency isolates failures but adds another integration to maintain. Browser/Electron adds runtime cost without an operator need. **Pick: Quickshell overlay provisionally**, taking “overlay above everything” literally. It removes the most custom desktop machinery. Confirm that a shell plugin counts as the requested native application and prove its keep-loaded lifecycle. If an independent binary is a requirement, choose standalone Qt and explicitly resolve the overlay dependency. [O E1, S E4-E7/E17, choice M]

- **F2. What happens on summon, blur and copy?** Cold starts save resident memory but repeatedly pay initialization and lose in-memory drafts. Resident single instance keeps search index and editing state, at a memory/startup cost. Minimize relies on WM recovery, hide has an explicit reopen path. **Pick: resident, hide rather than minimize**. Summon focuses search when idle and resumes the exact editor/cursor when a draft exists. Blur hides while keeping the draft. Successful copy closes the view and ends that draft. Keep unfinished values only in memory unless restart recovery is requested. Qt alternative needs close-to-hide plus quit-on-last-window behavior configured. [O E1, S E6-E7, choice M]

- **F3. Who owns GitHub login?** Reuse gh authentication with no duplicate token store, accepting its dependency and account permissions. Own OAuth device flow gives app-specific onboarding but adds registration, polling, secret lifecycle and keyring integration. Deploy key narrows clone access but makes account connection/repository discovery harder and adds SSH setup. **Pick: gh as connector**, invoke authenticated operations without extracting its token. Show account and selected owner/repository, explain missing auth/keyring problems, do not change global Git settings or log out the user's shared gh account on disconnect. App read-only behavior does not make a broad gh token read-only. [O E1, S E13-E14, choice M]

- **F4. What is synchronized?** App-owned Git clone supports history/incremental fetch but brings Git state and credential plumbing. Commit-pinned API snapshot avoids merge/worktree concerns but needs bounded download/extraction and commit resolution. Fetch each prompt live creates latency and mixed revisions. **Pick: read-only commit snapshot**, asynchronously resolve selected branch, download and validate a complete candidate, then atomically publish it as the local library/index. Start from the published local snapshot without network dependency. Refresh after summon when stale, plus manual refresh, showing revision/time/error. A first install without a valid snapshot must report that no library is available. Never update the template underlying an open draft. [O E1, S E4/E14, choice M]

- **F5. What repository format is the contract?** One Markdown file per prompt in category/subcategory folders stays editable in GitHub, while a JSON catalog is easier to validate but worse to author. Metadata categories duplicate folder state. **Pick: versioned root manifest plus `prompts/<category>/<subcategory>/<slug>.md`**, with categories as user-chosen names under a shared structural standard. Directory paths own categories. Minimal front matter owns stable id, title, optional description/tags and variable defaults/descriptions. Body stays literal UTF-8 prompt text. Agree exact schema and parser before implementation, including permitted depths/root prompts. Do not prescribe the user's category vocabulary. [O E1, S E3, design M]

- **F6. What does a variable represent after editing?** Regex-searching the changed body is cheap but loses slots as soon as braces disappear and treats pasted braces as new slots. A separate variable form has stable identity but changes the requested inline experience. Tracked editor ranges preserve inline editing at a higher undo/offset cost. **Pick: tracked slots initialized once from the immutable template**, Tab/Shift+Tab selects the complete token or its current value in body order. Repeated names provisionally share a value, with distinct names for independent values. Support multiline values and metadata defaults, display descriptions without adding them to output. Define one literal-token escape such as `\{{NAME}}`, emit it as literal braces, and never recursively interpret pasted values. Defaults must still be navigable. Full-body edits, range-crossing deletes and linked undo need a concrete interaction rule before this pick is settled. [O E1, S E15, semantics M. No stronger semantics found in inspected Qt or project files.]

- **F7. What does Ctrl+C mean?** Conventional selection-copy conflicts with the explicit operator shortcut. Context-sensitive selected/full copy can surprise users and change the result. **Pick: Ctrl+C in the prompt editor always exports the entire rendered prompt and closes only after clipboard success**, regardless of selection. Elsewhere it keeps conventional text behavior. Use plain-text output preserving whitespace. Decide an alternate selection-copy action only if needed. Unresolved required slots should keep the editor open with a clear reason. Hidden Qt instance could own the clipboard, but wl-copy provides ownership independent of app exit. No automatic typing/paste is requested. [O E1, S E15-E16, choice M]

- **F8. What does “smart search” mean?** Exact/prefix/substring is small and predictable but misses typos. Local fuzzy ranking handles imperfect recall but needs relevance examples and a library-size target. Embeddings/remote search adds index/runtime/network cost. **Pick: local deterministic fuzzy search**, exact and prefix titles first, then title/aliases/tags/category matches, with description/body matches lower and a stable title/id tiebreaker. Pre-index once per snapshot. Arrow keys choose, Enter and click open. Do not call GitHub per keystroke. Use operator examples to define ranking rather than treating “fuzzy” as acceptance evidence. [O E1, S E10, choice M]

- **F9. How do installation, updates, settings and appearance work?** Local makepkg install proves packaging but has no upstream update channel. AUR release package integrates existing updates but requires a maintainer and reproducible release sources. Custom pacman repository adds signing/hosting work. Mise and an app self-updater add another owner for a desktop installation. **Pick: PKGBUILD first, AUR release distribution when public updates are required**, no self-updater or mise. A plugin still needs a defined package-to-user-plugin registration path and removal behavior. Settings contain GitHub account status, repository/branch, sync state/manual refresh, disconnect, and summon shortcut integration. No color/ranking knobs are established requirements. Inherit all relevant theme roles live. Reuse shell motion behavior for a plugin, or extend the accent-only app Theme to the actual palette and watcher lifecycle for Qt. Never install user bindings by silently replacing an existing action. [O E1-E2, S E4-E5/E8-E9/E12/E17, choice M]

## 3. Practitioner questions / pitfalls

These are practitioner-style questions, not attributed practitioner advice.

- **R1. Can summon focus search over fullscreen, on the intended monitor, and after rapid hide/reopen?** Remove uncertainty with a real Hyprland interaction proof before committing F1. Floating/pin is not enough evidence. Release keyboard ownership immediately on hide. The local Tensaku focus handler is an observed test constraint, not a reason to edit unrelated configuration. [S E6/E11/E17, remedy M]
- **R2. What happens when a value contains emoji, line breaks, literal braces, or replaces several slots?** Avoid reparsing output and maintain slot identity separately. Test paste, range shifts, repeated variables, backward traversal and undo. Without a rule for edits across slot boundaries, full-body editing remains unsettled. [O E1, S E15, remedy M]
- **R3. Can the user switch to Chrome, copy a value, and resume without losing the current slot?** Keep editor state outside view visibility. Separate hide, copy-complete and discard transitions. Text letters such as Q, Space and ? must remain typeable, despite the generic app guide's global shortcut examples. [O E1, S E4/E6, remedy M]
- **R4. Does clipboard content survive close and paste correctly into Chrome and a terminal?** Verify actual pastes after hiding and quitting, including multiline/trailing newline content. Avoid clipboard-manager dependence and key injection. Close only on successful copy. Omarchy history may retain substituted private values, so memory-only drafts do not imply no retention anywhere. [S E16, remedy M]
- **R5. What happens after revoked access, an account switch, bad repository data, or a sync finishing after repository selection changes?** Bind work to selected account/repo/commit, reject obsolete responses, validate before publication, retain the explicit local snapshot with visible stale/error state. Retry transient external failures with warnings and then surface the last error with status/body/context, without credentials. Disconnect clears this app's library state, not gh login. [S E13-E14, remedy M]
- **R6. Can repository contents execute code or escape the cache directory?** Treat files as bounded data only. Reject unsafe archive paths/symlinks, unsupported schemas and malformed metadata at import. Do not execute repository scripts, render active HTML, evaluate templates, or recursively clone submodules. [M, no prompt-import contract exists in E3]
- **R7. Does a theme switch leave stale colors, bad selection contrast, or duplicate animations?** Use semantic palette roles and prove file/symlink replacement handling. Follow motion-off behavior, do not animate text input itself, and avoid stacking compositor and QML popup effects. [O E2, S E4/E8-E9, remedy M]
- **R8. Will a package upgrade actually install the new version?** Prove a package from a release source in a clean build, installation, upgrade and removal. The inspected source-empty checkout PKGBUILD is an installation starting point, not a complete AUR publishing recipe. Avoid ownership conflicts between package-managed plugin files and user modifications. [S E12/E17, remedy M]
- **R9. Which tests prove the job?** Parser/render/search tests cover malformed imports, literal escapes, repeated/default/multiline values and deterministic ranking. State/process tests cover failed sync/copy and preserved drafts. Offscreen tests cannot establish compositor focus or real clipboard delivery, so add a manual Hyprland keyboard/browser round trip and theme/motion/monitor checks. Measure summon/search against an agreed corpus and latency target. [O E1-E2, S E4/E6/E15-E16, scope M]

## 5. Which fork first and why

**Settle F1 first with a small desktop proof and operator acceptance of the surface.** It changes process ownership, focus/IPC, retained state, theme/animation integration, testing and installation. My provisional Quickshell pick follows the literal overlay requirement and the inspected working shell mechanisms. F6 is the next highest-risk fork: replacing braces in an ordinary editor is easy, retaining navigable variable identity through editing is not.
