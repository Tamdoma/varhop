# Chart review: slot C2 (2026-10-12)

Live checks run 2026-10-12 on the operator's machine: quickshell 0.3.2-4, qt6-base 6.12.0-2, gh 2.102.0 logged in as ivanjuras, git 2.56.0, `core.autocrlf` unset, no `GH_TOKEN`/`GITHUB_TOKEN`/`GH_HOST`/`GH_REPO` in the quickshell process environment.

## sync-and-auth picks

- S1 Q1 copy form: pick 1a (working shallow clone), only with two amendments. Without both, pick 1b (bare).
  - A1 Neutralize checkout transforms. B's fidelity objection (slots/sync-and-auth-rebuttal-B.md:5) is removable inside 1a: `$GIT_DIR/info/attributes` has the highest precedence over in-repo and global attributes (`man gitattributes`, "When deciding what attributes are assigned to a path", read 2026-10-12). Clone with `--no-checkout`, write a `prompts/**` line unsetting `text`/`ident` and unspecifying `eol`/`filter`/`working-tree-encoding`, then check out. Leaf proof: fixture repo with `.gitattributes` `*.md text eol=crlf` must read byte-identical to its blobs. C's probe (sync-and-auth-rebuttal-C.md RC1) only proved no transform happens on a repo with no attributes on this machine.
  - A2 No in-place reset of the active copy. `fetch` + `reset --hard` in the only clone destroys the previous good on-disk library before read/index run, so the settled "publish only after fetch, reset, read and index all succeed" (forks/sync-and-auth.md:22) only holds in memory. Shell restarts after a failed index and loads the half-published tree. Refresh the inactive of two clone slots and switch the active slot only after a successful index. Bare 1b gets this for free by pinning reads to a commit sha, which is its real advantage, not line endings.
  - Why not 1b as drawn: its reader is the expensive part. Quickshell's stream parser delivers decoded `QString` chunks (/usr/lib/qt6/qml/Quickshell/Io/quickshell-io.qmltypes:41-45), and `git cat-file --batch` frames by byte count. UTF-8 prompt bodies ("any types of spaces and signs", forks/repo-format.md:28) make byte framing over decoded text unsafe, so 1b means one `cat-file` Process per prompt or a byte-level parser QML does not naturally give. That buys nothing once A1+A2 land, since end-to-end fidelity is limited by `QString` decoding either way (see M1).
- S2 Q2 cooldown: pick 2b (5 min). The fetch is a git fetch on summon only, measured 0.9 s (sync-and-auth-C.md:11), not a REST call against the 5000/h quota. The binding parts are already settled: failed attempts start the cooldown, Ctrl+R bypasses. 5 vs 10 has no other cost argument, and 5 halves the stale window for the common case "edited a prompt elsewhere, summon varhop". Add: store the last-attempt time outside shell.json (see F3), recorded at attempt start so a hung fetch that times out still gates.
- S3 Q3 repo switch: pick 3a (keep old until new imports). 3b contradicts the fork's own publish-after-success rule (forks/sync-and-auth.md:22): a typo'd or newly-private repo would delete the only offline library. With A2's two slots, 3a is the same mechanism: clone the new repo into the inactive slot, index, then persist the selection and switch. Persist the settings write last; a restart mid-switch must still point at the old repo and its intact slot. Tag every async completion with a generation number so a cancelled switch cannot publish into the new selection.
- S4 Q4 account change: pick 4a (store login, reconfirm on change), plus store the numeric account id and repo id in settings. Do not key cache paths by them (4b). Reasons: one repo and one slot pair means path keying only accumulates orphan caches (sync-and-auth-rebuttal-C.md RC4). But a login string alone is the wrong identity: logins can be renamed and later reused, and a repo deleted and recreated under the same `owner/repo` name would silently inherit the old cache while offline. The picker already receives both numeric ids from `/user/repos` at no extra call. Mismatch on either id triggers the S3 switch path. Also adopt B's env scrub (sync-and-auth-rebuttal-B.md:11) via `env -u GH_TOKEN -u GITHUB_TOKEN -u GH_HOST -u GH_REPO` in argv: Quickshell `Process.environment` can only override values or clear the whole environment (/usr/lib/qt6/qml/Quickshell/Io/quickshell-io.qmltypes environment/clearEnvironment properties), and an empty-string token is not the same as an unset one. It costs one argv prefix and removes "works in my terminal identity, silently different in the shell".

- F2 The unproven core of form-factor is still open: own-id hide/toggle and a `{ panel = "ivan.varhop" }` binding (forks/form-factor.md:13). No installed third-party plugin on this machine is an overlay (~/.config/omarchy/plugins/ivan.*/manifest.json kinds are bar, bar-widget, service). If scoped overlay summon/hide does not work for a third-party id, the taken form fails at step 1. This proof should gate every other leaf, not ride along with the shell leaf.
- F3 Settings storage via `shell.updateEntryInline` writes into ~/.config/omarchy/shell.json, which the shell watches for changes (/usr/share/omarchy/shell/shell.qml:129,142 `watchChanges: true`). Selection data (repo, login, ids) belongs there. Anything written per refresh or per copy (cooldown timestamp, usage counts) does not: every write rewrites the watched shell config and risks reload churn in a keepLoaded plugin. Put volatile state in a state-dir file; keep shell.json writes to user-driven selection changes, always as the full object (already settled).
- F4 Front matter boundary is under-specified for the taken "arbitrary Markdown, copied verbatim" (forks/repo-format.md:28). A body that opens with a `---` rule, or a YAML example prompt, will be read as front matter; with no closing `---` the whole body can be swallowed. Lenient load shows an error, but the prompt is still broken. The leaf needs a hard rule (for example: front matter only when a closing `---` appears within the first N lines and every non-blank line matches the known-key line shape; otherwise the whole file is body). The same applies to the exact subset accepted for `tags` and quoted values: a hand parser that silently differs from YAML will misread valid files without error.
- F5 Token grammar details are not pinned by "uppercase-only A-Z, 0-9, underscore" (forks/repo-format.md Taken Q3): first character digit or underscore, `{{{NAME}}}`, `{{NAME}}` inside fenced code blocks (a prompt about templating becomes its own tab stops unless the author escapes every example), and whether copy strips the backslash in `\{{abc}}` when the name is not a valid token. Each is a one-line rule; without them the parser and the editor will decide by accident.

## Material gaps in the open forks

- M1 variable-editing: copy fidelity is decided by the editor widget, not the clone. Material the fork must settle: (i) the copied text is rebuilt from the stored body string plus variable values, not read back from a `TextEdit` document, which normalizes CRLF to LF and drops the trailing newline; proof fixture with CRLF, BOM, and final newline. (ii) Repeated `{{NAME}}`: one tab stop per unique name with all occurrences updating together, or one stop per occurrence (forks/repo-format.md settles shared value, not stop count). (iii) Typed or pasted value containing `{{OTHER}}` stays literal and never re-enters traversal. (iv) Whole body free-editable or variables only: a single editable `TextEdit` needs a segment model underneath either way, and Tab must be intercepted before the widget consumes it. (v) Search and editor should be real `TextInput`/`TextEdit`, not manual key catching like first-party overlays, so IME, dead keys, and Ctrl+V paste work.
- M2 copy-and-close: settle the clipboard mechanism, not only the key. `Quickshell.clipboardText` is settable (/usr/lib/qt6/qml/Quickshell/quickshell-core.qmltypes:998) and the shell process outlives the overlay. The first-party path /usr/share/omarchy/bin/omarchy-clipboard-paste-text:49-52 takes the text as argv, which puts the full prompt in the process list and caps its size. Pick clipboardText or wl-copy fed through stdin. Also missing: (i) Ctrl+C per stage: in the editor with ordinary text selected, Ctrl+C as taken copies the whole prompt and closes, destroying an in-progress edit when the user meant "copy this selection"; define search-stage vs edit-stage behavior and whether a non-variable selection changes it. (ii) Draft lifespan: hide/resume is settled for hide, but a shell reload, plugin update, or theme change recreates the plugin and drops an in-memory draft; state whether that loss is accepted or the draft persists. (iii) Summon while a draft exists resumes the draft or starts a fresh search, and what Esc does at each stage to the draft.
- M3 search: beyond fields and ranking, settle (i) empty-query list (all, recent, or by category) since typing-first Google-suggest gives no browse path when the user forgot a name; (ii) diacritic folding (čćžšđ in titles) and case rules in JS normalization; (iii) usage-based ranking needs a usage store, which per F3 must not live in shell.json; (iv) a refresh completing mid-search must keep selection by prompt id, not list position.
- M4 settings-and-hotkey: the fork must say who writes the Hyprland binding. First-party binds are static lines (/usr/share/omarchy/default/hypr/bindings/utilities.lua:3). Options differ materially: settings shows a line for the user to paste into their bindings file, or the plugin writes a file and reloads Hyprland. Include conflict handling (chosen combo already bound), what `omarchy plugin remove` leaves behind (dead binding, cache, shell.json entry), and first-run routing: hotkey with no repo chosen opens the picker, not an empty search.
- M5 sync leftovers no slot owns: (i) Empty GitHub repo (no commits) and repo with commits but no `prompts/` must be named states, not errors. The operator creates the repo from scratch (INTAKE.md, forks/repo-format.md Q5), so connecting before the first push is the expected first run. `fetch origin HEAD` on an unborn HEAD is the failure to handle. (ii) Typed `owner/repo` must be validated to a strict pattern before it reaches a URL, a filesystem path, or argv; clone commands use `--` and a constructed URL, never the raw typed string. (iii) Size guard: a depth-1 clone of an arbitrary picked repo downloads its full tree; the picker already has repo size from the API, so warn or refuse above a cap rather than timing out mid-clone. (iv) Process timeouts differ by operation: a single 20 s timeout that suits fetch will kill a legitimate first clone on a slow link. Quickshell `Process` has no timeout property, so the leaf needs a Timer plus kill per process type.
